# ゾンビアポカリプス 難易度設計

「進行度に応じてゾンビの強さ・出現量が変わる」を、**数値で検証できる形**で設計したドキュメント。
モデル本体は Minecraft 非依存の純Java(`difficulty/`)で、`tools/DifficultySim.java` が戦闘をモンテカルロでシミュレートして設計目標を検証する。
CIで毎回 `./tools/run-sim.sh` が走り、**目標から外れる数値変更はビルドが失敗する**。

## 1. 設計原則

1. **相対難易度を一定に保つ**: ステージが上がっても「装備が標準なら、通常の夜の襲撃で失う体力は約3〜6割」に収める。絶対値(HP・攻撃)は上がるが、プレイヤーも強くなるので体感の緊張感は維持される。
2. **数ではなく強さ・種類・持続で圧力をかける**: バニラのプレイヤーは被弾後0.5秒の無敵時間があり、何体に囲まれても被ダメージは約2回/秒で頭打ちになる。数だけ増やしても危険度は伸びない(戦闘が長引くだけ)ため、出現数は控えめにし、能力・特殊個体・ノックバック耐性・毒ガス・ドア破壊で圧力をかける。
3. **備えが報われる**: ホードは「素の近接・開けた場所」では致命的(S2以降の死亡率50%以上)。一方で「盾・回復の備え + 通路での防衛」なら全ステージで凌げる(死亡率10%以下)。拠点防衛こそが攻略。
4. **理不尽を避ける(救済)**: 装備が標準より弱いプレイヤーは自動で緩和(DDA)。最後の死亡からの経過日数ボーナスは死亡でリセットされ、特別な救済処理なしに緩む。体力が35%未満で被弾直後は新規スポーンを見送る。
5. **予告と目印**: ホードナイトは固定周期(既定7日)で、夕方に警告メッセージが出る。特殊ゾンビは装備・パーティクルで見分けがつき、アルファは発光して壁越しに見える。

## 2. 進行度 → 脅威レベル

```
ステージ S (0..10)   … バニラの進捗(advancement)の達成状況から導出。セーブに残るので追加の保存データ不要
progress  = S + min(1.0, 0.12 × 最後の死亡からの日数) + min(0.5, 0.02 × 世界日数)
adj       = clamp( ln(装備Power / progressの標準Power) × 2.0 , -2.0, +0.8 )    … DDA。装備Power=√(実効HP × 対ゾンビ攻撃)
statLevel = progress + adj          → ゾンビの能力・種類・日光耐性
spawnLevel= progress + 0.4 × adj    → 出現量(装備による増減は能力より穏やかに)
```

| Stage | 達成条件(いずれか) |
|---|---|
| 1 | 石のツルハシ |
| 2 | 鉄の精錬 |
| 3 | 鉄の防具 / 鉄のツルハシ |
| 4 | ダイヤモンド |
| 5 | ネザー突入 |
| 6 | ネザー要塞 / ブレイズロッド |
| 7 | 要塞発見(エンダーアイ) |
| 8 | エンド突入 |
| 9 | エンドラ討伐 |
| 10 | (エンドラ討伐後に)ネザライト装備 / ウィザー召喚 / フルビーコン |

ドラゴン討伐前にウィザーを召喚しても10にはならない(飛び級防止)。

## 3. ゾンビの強さ(脅威レベル L に対する倍率)

|---|---|---|---|---|---|---|
| 0 | ×1.00 | ×1.00 | ×1.00 | 0 | 35 | 0 |
| 3 | ×1.45 | ×1.30 | ×1.04 | +2 | 44 | 0 |
| 5 | ×1.95 | ×1.70 | ×1.08 | +4 | 50 | 0.06 |
| 7 | ×2.40 | ×2.05 | ×1.12 | +6 | 56 | 0.12 |
| 10 | ×3.00 | ×2.50 | ×1.18 | +12 | 64 | 0.20 |

速度は上限1.45倍(プレイヤーのスプリントを超えない)。バニラ Hard はダメージ1.5倍が別に掛かるため、Hard では本mod分に ×0.8 を掛ける。

## 4. 出現量

| 項目 | 式 |
|---|---|
| 環境グループ(夜の散発的な襲撃) | 平均 `2 + 0.5L` 体、周期 90秒(L0)→26秒(L11)、周囲48ブロックの上限 `6 + 1.8L` |
| 昼 | L4以上のみ、周期2.5倍、暗い場所(洞窟・日陰)のみ |
| ホードナイト | 既定7日ごと(7日目・14日目…)の夜。波数 2(L<2.5)/3/4(L≥8)、1波平均 `3 + 0.55L` 体、波間隔 `28 - 1.2L` 秒(最小15)、同時上限 `12 + 3L` |
| 指揮官 | L≥6 で第1波に1体(L≥9は2体)、L≥8 は中盤の波にも1体 |
| 緩和 | ホード後 120秒は環境スポーン停止。体力35%未満+被弾直後は新規スポーン見送り |
| 絶対上限 | 周囲48ブロックに `maxNearbyZombies`(既定60) |

ホード中はベッドで夜を飛ばせない(設定で解除可)。

## 5. シミュレータの戦闘モデル(`tools/DifficultySim.java`)

バニラ準拠: ゾンビ近接は1秒に1回、防具式(armor/toughness/EPF)、被弾後0.5秒の無敵時間。
プレイヤー: 剣 1.6回/秒・命中90%・クリティカル混在で平均×1.2・自然回復 4秒に1HP。被弾した個体はノックバックで0.8秒攻撃できない(KB耐性で短縮=スタンロック)。接敵直後0.9秒はプレイヤーのリーチで先制できる。
装備ベンチマーク(`GearBench`)は各ステージの「標準的な装備」(革→鉄→ダイヤ→ネザライト + 対アンデッド特攻)。盾・金リンゴ・弓・地形は含めない=**実プレイはこれより有利**。

能力・出現数カーブの単調性、速度上限、`statScale=0`でバニラ同等、進捗の飛び級防止、ホード周期。

## 6. 既知の限界と未検証事項

- **ゲーム内で未プレイ**。数値の絶対的な較正はシミュレータ上のもの(`ZOMBIE_LAND=0.75`などのプレイヤー操作パラメータはS0基準の仮置き)。実プレイで `/zapoc info` と `/zapoc override <L>` を使って各レベルを試し、体感がずれていれば `tools/DifficultySim.java` の定数と `ZombieProfile` のカーブを調整する。
- ブローターの毒ガス、アルファのオーラ、ドア破壊は挙動をモデル化しているが、実際のAI(経路探索・ドアの破壊時間12秒)との相互作用は未確認。
- マルチプレイは「最寄りプレイヤー基準」で強化し、ディレクターはプレイヤーごとに独立して動く。複数人が近いと合算でゾンビが増える(`maxNearbyZombies` で頭打ち)。
